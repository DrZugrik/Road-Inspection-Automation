# Road Inspection Automation

`Road Inspection Automation` — Python-проект для пакетного формирования Word-отчётов по обследованию автомобильных дорог. Он объединяет данные Excel, DOCX-шаблон и фотоматериалы объекта в итоговый `.docx`, а также формирует JSON-манифесты и журналы выполнения.

> Рабочая ветка улучшений: `improve/safe-docx-placeholders`. Ветка `main` сохраняет исходное опубликованное состояние.

## Возможности

- обработка одного объекта, набора явно указанных объектов или всех подпапок каталога;
- извлечение метаданных дороги из Excel-каталога;
- заполнение текстовых плейсхолдеров Word без пересоздания абзацев и ячеек;
- построение таблиц по продольной/поперечной ровности, дефектам, прочности и ширине;
- единая обработка Excel-данных ширины для таблицы, метаданных и выбора фото min/max;
- извлечение схемы ширины из XLSX;
- вставка фото кернов, шурфов, прочности, ширины и общих видов дороги;
- журналирование и сводный JSON-статус по каждой обработанной папке;
- необязательное обновление полей Word (`SEQ`) через Microsoft Word COM.

## Требования

### Платформа

- Windows 10/11;
- Python 3.12+ (текущая проверенная среда — Python 3.12.1);
- Microsoft Word нужен только для обновления полей Word через COM. Для запуска без Word используйте `--skip-com-update` либо `update_word_fields = false`.

### Пакеты Python

Проект использует:

- `pandas`, `numpy`, `openpyxl` — Excel;
- `python-docx`, `lxml` — Word;
- `Pillow` — изображения;
- `pywin32` — необязательное COM-обновление полей Word;
- `python-dateutil`.

Корневой `requirements.txt` пока не создан. Используйте существующее рабочее виртуальное окружение или установите перечисленные пакеты вручную до подготовки полноценной спецификации зависимостей.

## Быстрый старт

### 1. Подготовьте окружение

```powershell
cd D:\ProgrammEngine\road_inspection_automation
& .\venv\Scripts\python.exe --version
```

### 2. Создайте локальную конфигурацию

Скопируйте пример. Локальный `config.toml` не попадёт в Git.

```powershell
Copy-Item .\config.example.toml .\config.toml
```

Заполните пути в `config.toml`:

```toml
template_path = "D:/data/template/template_6.docx"
catalog_path = "D:/data/template/catalog.xlsx"
source_dir = "D:/data/objects"
output_dir = "D:/data/output"

# true — source_dir содержит папки объектов;
# false — source_dir является одной папкой объекта.
process_subfolders = true

# false — не требуется установленный Microsoft Word.
update_word_fields = false
log_level = "INFO"
```

### 3. Запустите пакетную обработку

```powershell
& .\venv\Scripts\python.exe .\main.py --config .\config.toml
```

## Настройка и приоритет параметров

Источники параметров применяются в следующем порядке:

1. аргументы командной строки;
2. файл, переданный через `--config`;
3. переменные окружения `ROAD_INSPECTION_*`;
4. значения по умолчанию (только для `output_dir`, `update_word_fields`, `log_level`).

Обязательны путь к шаблону, Excel-каталогу и как минимум один источник папок: `--source`, `--folder` или `folders_to_process` в TOML.

### Аргументы CLI

| Аргумент | Назначение |
| --- | --- |
| `--config PATH` | TOML-файл конфигурации |
| `--template PATH` | DOCX-шаблон |
| `--catalog PATH` | Excel-каталог объектов |
| `--source PATH` | один объект или каталог объектов |
| `--folder PATH` | конкретная папка объекта; можно повторять |
| `--output-dir PATH` | каталог результатов |
| `--process-subfolders` | обработать все подпапки `--source` |
| `--skip-com-update` | не обновлять поля Word через Microsoft Word |
| `--log-level LEVEL` | `DEBUG`, `INFO`, `WARNING` или `ERROR` |

### Примеры запуска

Один объект без COM:

```powershell
& .\venv\Scripts\python.exe .\main.py `
  --template "D:\data\template\template_6.docx" `
  --catalog "D:\data\template\catalog.xlsx" `
  --source "D:\data\objects\Проезд Энергетиков" `
  --output-dir "D:\data\output" `
  --skip-com-update
```

Несколько объектов:

```powershell
& .\venv\Scripts\python.exe .\main.py `
  --template "D:\data\template\template_6.docx" `
  --catalog "D:\data\template\catalog.xlsx" `
  --folder "D:\data\objects\Объект 1" `
  --folder "D:\data\objects\Объект 2" `
  --output-dir "D:\data\output" `
  --skip-com-update
```

Переменные окружения:

```powershell
$env:ROAD_INSPECTION_TEMPLATE = "D:\data\template\template_6.docx"
$env:ROAD_INSPECTION_CATALOG = "D:\data\template\catalog.xlsx"
$env:ROAD_INSPECTION_SOURCE = "D:\data\objects"
$env:ROAD_INSPECTION_OUTPUT_DIR = "D:\data\output"
& .\venv\Scripts\python.exe .\main.py --process-subfolders --skip-com-update
```

## Входные данные

### Excel-каталог объектов

Название папки объекта используется для поиска строки дороги. Ожидаются колонки (с некоторой вариативностью названий):

- `№ п/п`;
- `Участок`;
- `Наименование дороги`;
- `Балансодержатель автомобильной дороги`;
- `Идентификационный номер`;
- протяжённость: `Протяженость(Линейная)`, `Протяженость`, `Протяженность`, `Длина` или подобный вариант.

### Excel-файлы в папке объекта

| Данные | Фрагмент имени файла |
| --- | --- |
| Продольная ровность | `Продольная ровность покрытия` |
| Поперечная ровность | `Поперечная ровность покрытия` |
| Дефекты | `Дефекты покрытия` |
| Прочность | `Прочность дорожной одежды` |
| Ширина | `Ширина проезжей части` |

Файл ширины поддерживает два формата:

1. строка заголовков определяется автоматически по колонке с текстом `Ширина` в первых 20 строках;
2. устаревший формат: заголовки на строке 13, данные начинаются со строки 15.

Значения ширины `7,25`, `7.25` и значения с пробелами нормализуются. Для отчёта они отображаются с одной цифрой после запятой. Координаты min/max берутся из `Местоположение`/`км+м`, а не из порядкового номера записи.

### Фотографии

- `Фотоматериалы кернов и шурфов/Образец № <номер>/` — керны и шурфы;
- папка с фрагментом `измерения прочности` — прочность;
- `Фотоматериалы <название папки объекта>` — общие виды;
- поддерживаемые форматы: `.jpg`, `.jpeg`, `.png`; в отдельных операциях `.bmp` и `.tiff`.

## Плейсхолдеры DOCX

### Метаданные

```text
{{НОМЕР_ПП}}                 {{НОМЕР_УЧСТОК}}
{{ДОРОГА_ИД}}                {{ДОРОГА_НАЗВАНИЕ}}
{{ДОРОГА_НАЗВАНИЕ_ПАПКА}}    {{ДОРОГА_НАЗВАНИЕ_EXCEL}}
{{БАЛАНСОДЕРЖАТЕЛЬ}}         {{ДОРОГА_ДЛИНА}}
{{ДОРОГА_ШИРИНА_MIN}}        {{ДОРОГА_ШИРИНА_MAX}}
```

### Таблицы и схема

```text
{{ТАБЛИЦА_ПРОДОЛЬНАЯ_ДАННЫЕ}}
{{ТАБЛИЦА_ПОПЕРЕЧНАЯ_ДАННЫЕ}}
{{ТАБЛИЦА_ДЕФЕКТЫ_ДАННЫЕ}}
{{ТАБЛИЦА_ПРОЧНОСТЬ_ДАННЫЕ}}
{{ТАБЛИЦА_ШИРИНА_ДАННЫЕ}}
{{ТАБЛИЦА_ШИРИНА_СХЕМА}}
```

### Фото и подписи

```text
{{ФОТО_ШУРФ_КЕРН}}           {{ФОТО_ПРОЧНОСТЬ}}
{{ПИКЕТ_ПРОЧНОСТЬ}}          {{ФОТО_ШИРИНА_MIN}}
{{ФОТО_ШИРИНА_MAX}}          {{ПИКЕТ_ШИРИНА_MIN}}
{{ПИКЕТ_ШИРИНА_MAX}}
{{ФОТО_ВИД_ДОРОГА_1}} ... {{ФОТО_ВИД_ДОРОГА_7}}
{{ФОТО_ВИД_ДОРОГА_ПИКЕТ_1}} ... {{ФОТО_ВИД_ДОРОГА_ПИКЕТ_7}}
```

Текстовые подстановки выполняются модулем `docx_placeholders.py`. Он заменяет маркер в существующих `runs`, поэтому плейсхолдер может быть разбит Word между несколькими фрагментами с разным форматированием. Обход включает основной текст, таблицы, вложенные таблицы и колонтитулы.

## Результаты и статусы

Для объекта создаются:

- `<название>_report.docx` — итоговый Word-отчёт;
- `<название>_report.json` — данные по обработанным таблицам;
- `logs/run_<дата-время>.log` — журнал запуска;
- `run_manifests/run_<дата-время>.json` — сводный результат пакетной обработки.

Статус объекта в сводном манифесте:

- `success` — все табличные элементы обработаны;
- `completed_with_warnings` — создан отчёт, но часть таблиц/схем не обработана;
- `failed` — папка не существует или произошла критическая ошибка.

Процесс завершается с кодом `1`, если хотя бы одна папка имеет статус `failed`; код `2` означает ошибку конфигурации либо отсутствие шаблона/каталога.

## Тестирование

Проверка синтаксиса:

```powershell
& .\venv\Scripts\python.exe -m py_compile `
  .\main.py .\photos_processor.py .\width_data.py .\docx_placeholders.py `
  .\app_config.py .\logging_utils.py .\run_manifest.py
```

Запуск набора тестов:

```powershell
& .\venv\Scripts\python.exe -m unittest discover -s .\tests -v
```

Тесты покрывают конфигурацию, сводные манифесты, оба формата Excel ширины, расчёт min/max и безопасную подстановку DOCX-плейсхолдеров в обычном тексте, ячейках и колонтитулах.

## Текущие ограничения

- детальная диагностика старых процедур работы с фото пока частично использует `print()` вместо `logging`;
- вставка изображений пока намеренно очищает целевой абзац/ячейку: это отдельный сценарий замены содержимого и следующий кандидат на рефакторинг;
- выбор тематических Excel-файлов и фотопапок основан на фрагментах имён;
- обновление полей `SEQ` через COM требует Microsoft Word;
- отсутствует корневой `requirements.txt`/`pyproject.toml`.

План следующих улучшений приведён в [IMPROVEMENTS_FOR_DISCUSSION.md](IMPROVEMENTS_FOR_DISCUSSION.md).
